# Example 1: Six-Method Comparison for Constrained Biobjective Optimization

This directory contains the reproducible computational workflow for
**Example 1**, a five-variable constrained biobjective optimization
problem used to compare six multiobjective optimization methods:

1.  Proposed homotopy continuation method
2.  Weighted Sum
3.  Global Criterion
4.  NSGA-II
5.  Lexicographical optimization
6.  $\epsilon$-Constraint

The workflow is intentionally separated into **computation** and
**post-processing**. Raw numerical results are stored in
`example1_results/`, while final figures and comparison tables are
stored in `example1_figures/`.

## Optimization problem

The two objectives are

$$
f_1(x)=x_1^2+x_2^2+x_3^2+x_4^2+x_5^2,
$$

and

$$
f_2(x)=3x_1+2x_2-\frac{1}{3}x_3+0.01(x_4-x_5)^3.
$$

The problem is subject to the inequality constraint

$$
g(x)=x_1^2+x_2^2+x_3^2+x_4^2-10\le 0,
$$

and the equality constraints

$$
h_1(x)=4x_1-2x_2+0.8x_3+0.6x_4+0.5x_5^2=0,
$$

$$
h_2(x)=x_1+2x_2-x_3-0.5x_4+x_5-2=0.
$$

The common problem definition and shared numerical settings are
maintained in `common_problem.py`.

## Running the example

### 1. Generate the projected feasible background

Run

``` bash
python projectedFeasibleGenerator.py
```

The script generates projected feasible points used as the background in
the Pareto-front figures and saves

``` text
example1_results/projected_feasible_solution.csv
```

The generator samples 20,000 candidate points and projects them onto the
constrained feasible set.

### 2. Run all six optimization methods

Run

``` bash
python example1_run_all_methods.py
```

This is the main numerical experiment. It runs the six comparison
methods and saves their raw solution data in

``` text
example1_results/
```

The principal output files include

``` text
solution_homotopy_ex2_python_endpoint_corrected.csv
solution_weighted_sum.csv
solution_global_criterion.csv
solution_lexicographical.csv
solution_epsilon_constraint.csv
solution_nsga2_eqtol_1em01.csv
solution_nsga2_eqtol_1em02.csv
solution_nsga2_eqtol_1em03.csv
solution_nsga2_eqtol_1em04.csv
method_timing_summary.csv
```

For NSGA-II, the main comparison uses the equality-feasibility band

$$
\epsilon_h=10^{-2},
$$

and the additional values

$$
10^{-1},\;10^{-2},\;10^{-3},\;10^{-4}
$$

are retained for the equality-tolerance sensitivity study.

### 3. Produce final metrics and figures

After the numerical runs have completed, execute

``` bash
python example1_postprocess_final.py
```

This script **does not rerun the optimization methods**. It reads the
CSV files from `example1_results/`, performs the final common
post-processing, and writes the publication outputs to

``` text
example1_figures/
```

The outputs include the corrected empirical reference front, feasibility
summary, normalized comparison metrics, pairwise Hausdorff distances,
timing summary, the six-method comparison figure, the NSGA-II
equality-tolerance sensitivity figure, and Homotopy-versus-Weighted-Sum
diagnostic figures.

## Empirical reference front

For the final quantitative comparison, the empirical reference front is
constructed from the nondominated union of the highly feasible solutions
generated by the deterministic front-generating methods:

-   Homotopy
-   Weighted Sum
-   Global Criterion
-   $\epsilon$-Constraint

A solution is eligible to define this reference when

$$
|h_1(x)|\le 10^{-8},\qquad
|h_2(x)|\le 10^{-8},\qquad
g(x)\le 10^{-8}.
$$

NSGA-II is deliberately **not** used to construct the empirical
reference because its equality-feasibility band is itself part of the
sensitivity analysis. Lexicographical optimization is also excluded from
constructing the reference because it naturally returns only the two
priority-order endpoint solutions.

All six methods are nevertheless evaluated against the same reference
front.

## Comparison metrics

The final post-processing reports metrics in normalized objective space,
including:

-   number of raw and nondominated solutions;
-   GD (root-mean-square distance from a method front to the empirical
    reference);
-   IGD (mean distance from the empirical reference to the method
    front);
-   symmetric Hausdorff distance;
-   mean and standard deviation of adjacent-point spacing;
-   spacing coefficient of variation;
-   maximum adjacent-point gap;
-   objective-range coverage;
-   maximum equality residual;
-   maximum inequality residual; and
-   fraction satisfying the strict common feasibility tolerance.

Smaller GD, IGD, Hausdorff distance, spacing coefficient of variation,
and maximum gap generally indicate better agreement or distribution with
respect to the empirical reference. Coverage values near one indicate
broad coverage of the reference objective range. Feasibility statistics
should be considered together with front-quality metrics, particularly
for NSGA-II.

## Figures

The principal six-method figure displays the computed solutions as
**unconnected open circles** over the projected feasible objective
region. The six panels correspond to

1.  Homotopy
2.  Weighted Sum
3.  Global Criterion
4.  NSGA-II
5.  Lexicographical
6.  $\epsilon$-Constraint

The post-processing script also produces a separate NSGA-II
equality-tolerance sensitivity figure and Homotopy-versus-Weighted-Sum
diagnostics.

## Reproducibility notes

-   The same five-variable optimization problem is used for all six
    methods.
-   Equality constraints are retained explicitly for NSGA-II; they are
    not analytically eliminated.
-   Lexicographical optimization retains its natural two priority-order
    solutions rather than being artificially expanded into a sampled
    front.
-   NSGA-II uses a fixed random seed for reproducibility.
-   The homotopy method retains its prescribed initialization rather
    than projecting the initial point onto the equality-constraint
    manifold.
-   The final post-processing uses one common empirical reference and
    one common normalization for method comparison.
-   Raw numerical results and publication outputs are kept in separate
    directories to avoid mixing computational data with figures and
    summary tables.

## Optional diagnostic scripts

`diagnosticSampling.py` and `feasibility.py` provide supplementary
random-sampling diagnostics for examining how equality-feasibility
tolerances affect the apparent feasible objective region. They are not
required for the main six-method workflow.

## Recommended workflow

For a complete rerun of Example 1:

``` bash
python projectedFeasibleGenerator.py
python example1_run_all_methods.py
python example1_postprocess_final.py
```

After these commands finish:

-   inspect `example1_results/` for the raw computational data;
-   inspect `example1_figures/` for the final comparison tables and
    publication figures.
